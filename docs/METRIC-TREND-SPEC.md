# 头颈癌工作台 指标趋势 Tab 设计确认表

状态：**已填实测值，待开发者确认**（2026-10-25）。通用规范：[24-METRIC-TREND-TAB-DESIGN.md](../docs/24-METRIC-TREND-TAB-DESIGN.md)。模板生成成功不表示业务接通。

| 事项 | 项目填写 |
| --- | --- |
| 用户/场景/一次任务 | 患者本人（家属代记为高频旁路，DESIGN-08）。放疗结束三个月，想知道「体重掉了多少、血象有没有掉、肾功能还够不够、嘴还能张开多少」，并把这些变化对上「手术 / 放疗起止 / 发音管置入」四个时间点。一次任务：首页 →「指标分析」→ 指标卡片看最近值与差值 → 翻卡看趋势 → 切「一图秀」把四条线和治疗事件对时间 → 回首页。 |
| 病情整理导航及旧入口映射 | 本项目为 **10 一级 / 34 二级**（`docs/SCENARIOS.md`）。指标相关分布在两处：**「指标分析」**3 个二级（指标卡片 / 一图秀 / 分级说明）+ **「资料与导出」**第 1 项（我的资料与草稿，含来源与核对）。**如实记偏离**：24 号文档要求五 Tab（来源→核对→档案→分类指标→汇总）串成一条，本项目拆成两个一级入口。理由：头颈癌的资料以病理报告、放疗记录、检验单为主，逐份「来源→核对」属于「我的病」路径下的事，硬塞进指标页会让指标页变成资料页。**未批准**（待开发者确认）。疾病特有入口不删除：张口度、发音管、气道、吞咽四条线各自有独立页面，指标页只读它们的数。 |
| 分类定义唯一文件、组顺序/项数口径 | 唯一来源：`prototypes/v0.1/index.html` 的每档案 `metrics` 数组（`track` 字段：`A` 血液 / `B` 内分泌 / `C` 营养 / `D` 功能）。组顺序固定 **A→B→C→D**，两页（指标卡片 / 一图秀图例）读同一数组，组名与顺序一致。项数：**8 项**（A 4：alb/hb/cr/anc；B 1：tsh；C 1：weight；D 2：mouth/mucositis）。 |
| 指标定义/别名/可接受单位来源 | 8 项定义见 `docs/ONE-CHART-SPEC.md` §2。单位取国内检验报告惯用：`g/L`、`μmol/L`、`mIU/L`、`10⁹/L`、`mm`、`kg`。分级标准：alb/hb/cr/anc 对照 **CTCAE v5.0**；mucositis 对照 **WHO 分级**（EV-01/EV-02：该共识只纳入 WHO 与 RTOG，原文「目前尚无证据显示哪一种分级标准更优」→ 本项目选 WHO 并写明口径）；**tsh / mouth / weight 无分级标准**，卡片显示「无分级标准」而不是硬套一个。 |
| SQLite表/字段与来源修订的映射 | 目标表：`metric_definitions(code, label, unit, track, grade_standard, version)` + `observations(subject_id, metric_code, on_date, value_num, value_text, absence_state, lab_name, method, source_ref_id)`。**原型无持久化**：`SUBJ().metrics` / `SUBJ().obs` 是内存演示数组，刷新即回到初始值；`STATE` 是**纯内存对象**：实测 `grep -c localStorage prototypes/v0.1/index.html` = **0**，刷新即回到初始页，连页签都不记。如实写「原型未接数据库、也未做本地持久化」，不写成已落库。 |
| 单位/方法/机构可比组策略 | 同指标换**机构或方法**即断线并拆可比组。已覆盖两组：`alb`（演示医院检验科·溴甲酚绿法 → 演示社区医院·免疫比浊法，2026-09-20）、`cr`（酶法 → 苦味酸法，2026-09-20）。`weight` 为家用体重秤单组；`mouth` 为门诊量尺单组。分组键 = `lab_name + method`。 |
| 未知日期/文本值/同日多次 | 日期缺失：不进折线，进「待核对」。文本值（如细胞学「阴性」、分级「2 级」）：不折线。同日多次：折线取当日最后一次，卡片「共 N 次记录」按原始条数算，不合并掉。 |
| 最近报告ID/修订版聚合规则 | 原型无报告实体，按 `obs` 单条计。生产口径：`documents` 以 `sha256` 去重、修订版取最新 `revision`，`observations` 指向 `source_ref_id`；同一天同一指标同一方法出现两次时以 `revision` 大者为准，并在卡片「来源」里可点开看是哪一份。 |
| 卡片高/字阶/2列→1列阈值/大字 | 卡片高 **276px 固定**（390 宽实测 276，内容不撑开）。2 列 → 1 列阈值：容器 **700px**。大字模式：**340px**（未实测）。数值字阶为卡片内最大字号，单位小一号。 |
| 3D翻面、来源点命中、键盘/读屏 | 翻面：`preserve-3d` + `rotateY`，翻转态是**单卡布尔值**（`data-flipped` + `aria-pressed`），不是 Set。背面 `inert` + `aria-hidden="true"`，翻转后正反面互换。键盘：卡片 `tabindex=0`、`role=group`、`aria-label` 带「可翻转查看趋势」。来源点：原型只做 SVG `<title>` 悬停，**点选不出详情、不回源**（见 ONE-CHART-SPEC R9 偏离）。读屏实测：**未做**。 |
| 0/1/多条及跨方法测试数据 | 已覆盖：**0 条**（空窗口 →「所选时间窗内没有记录」）；**1 条**（mucositis →「仅一次记录，无法比较」）；**多条**（weight 6 / alb 4 / hb 4 / cr 4 / mouth 4 / anc 3 / tsh 2）；**跨方法**（alb、cr 各 2 组）。合成数据，档案名「演示」开头，`lab` 字段一律「演示医院检验科 / 演示社区医院」。 |
| HTML版本/路径/hash/截图 | v0.1，`prototypes/v0.1/index.html`。文件哈希与截图清单见 `docs/PROTOTYPE-REVIEW.md`、`docs/DEMO-INDEX.md`。C1–C12 实测脚本：`scripts/measure-one-chart.py`（真浏览器 `channel='chrome'`）。 |
| 开发者确认版本、日期、模块范围 | **待确认**（不默认签认）。待确认范围：指标卡片（8 卡 / 276px / 翻转）、一图秀（3 条默认 / 治疗节点 / 时间窗）、分级说明页。 |
| MT01–MT15结果/证据/偏差 | 已实测：MT 卡片固定高 276、翻转不位移（Δ=0）、翻转态独立（`[true,false×7]`）、0/1/多条三态文案、跨方法分组、组顺序 A→B→C→D 两页一致、`aria-pressed` 与 `inert`。**未测**：读屏软件实际朗读、大字模式（340px）、700px 阈值切换、来源点命中回源（未实现）。**不凭「24/24 自检通过」算 UI 通过**——自检脚本覆盖的是页面级断言，不等于 MT 全项。 |
| Desktop app/profile/RC与人工验收 | **未实机验证**。本项目尚未装进 DSH Desktop（无 remote 仓、未打包）。 |

接口/数据库变化需单列迁移与旧数据兼容，不因增加分类Tab而另存重复病历。本项目新增普通指标走 `metric_definitions` 插行、**不迁移**；新增一类检查（如新增「肺功能」）才做结构迁移。
